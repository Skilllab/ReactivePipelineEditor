# ADR 003 — Использование record struct для NodeId, PipelineId, ConnectionId

Дата: 2026-09-14  
Статус: принято

#Контекст
- В кодовой базе идентификаторы сущностей (`NodeId`, `PipelineId`, `ConnectionId`) логически являются GUID, но разные семантические идентификаторы нельзя путать между собой.
- В проекте идентификаторы реализованы как:
  - `public readonly record struct NodeId(Guid Value)`
  - `public readonly record struct PipelineId(Guid Value)`
  - `public readonly record struct ConnectionId(Guid Value)`

#Решение
- Представлять идентификаторы в виде `readonly record struct` вместо "сырых" `Guid` или `struct`/`class` вручную.
- Предоставить конструкторы/фабрики: `New()` (генерация), `From(Guid)` (валидация), переопределить `ToString()`.

#Причины (обоснование)
1. Явная семантика и типобезопасность
   - `NodeId`, `PipelineId`, `ConnectionId` — разные типы, компилятор предотвратит их неумышленное смешивание.
2. Валидация в одном месте
   - `From(Guid)` предотвращает использование `Guid.Empty` и фиксирует доменную инварианту.
3. Иммутабельность и удобство
   - `record struct` генерирует корректные реализации равенства, `Deconstruct` и компактный синтаксис.
4. Производительность и экономия аллокаций
   - Как value-type, `record struct` избегает heap-аллокций в простых сценариях и уменьшает нагрузку на сборщик мусора по сравнению с `class`-обертками.
5. Читаемость и намерение
   - Код явно выражает доменную модель: типы идентификаторов — не просто `Guid`.
6. Сериализация/интероп
   - Простая структура с единственным `Guid`-полем легко сериализуется/десериализуется и совместима с внешними интерфейсами (при условии явной поддержки).

#Альтернативы и причины отказа
- Использовать сырые `Guid`:
  - Проще, но теряется типобезопасность и семантика; повышается риск ошибок (подмена id).
- `readonly struct` без `record`:
  - Можно, но придется вручную реализовать `Equals`, `GetHashCode`, `Deconstruct` и т. п.
- `sealed class`-обертка:
  - Позволяет nullability и референсную семантику; вводит дополнительные аллокации и сильнее влияет на GC.

#Недостатки / компромиссы
- Копирование value-type при частых передаваемых по значению больших структурах — здесь несущественно (внутри только `Guid`).
- При межпроцессном взаимодействии/рефлексии нужно учитывать конкретную форму сериализации.
- `record struct` поведение при boxing — аналогично другим value-type; необходимо избегать ненужного бокса.

#Примеры использования
- Создание: `var id = NodeId.New();`
- Валидация извлеченного GUID: `var id = NodeId.From(guidValue);`

#Вывод
- `record struct` оптимально сочетает типобезопасность, доменную ясность и производительность для простых идентификаторов, представленных одним `Guid`. Рекомендуется сохранять текущую реализацию и применять аналогичный подход для других доменных идентификаторов.
