# ADR 0003 — Использование иерархической системы типов DataType

Дата: 2026-09-15  
Статус: принято

## Контекст

В проекте `ReactivePipelineEditor` узлы обрабатывают потоки данных через порты (входные и выходные). 
Для обеспечения корректности соединения портов и валидации типов данных между узлами требуется:
- Механизм проверки совместимости типов данных
- Ковариантная иерархия типов (допуск более специализованных типов на место базовых)
- Расширяемость на новые типы данных
- Сохранение метаинформации типов для сериализации и отладки

В файле `src/ReactivePipelineEditor.Domain/Ports/DataType.cs` определен тип:
```
public sealed record DataType(string Name, DataType? BaseType = null)
{
	public static readonly DataType RawRecord = new("RawRecord");
	public static readonly DataType Record = new("Record", RawRecord);
	public static readonly DataType Aggregate = new("Aggregate", Record);
	public bool IsAssignableFrom(DataType other) { /* ... */ }
}
```

## Решение

- Использовать `DataType` как **value object** (через `sealed record`) для представления типов данных в конвейере.
- Определить **трехуровневую иерархию типов**: `RawRecord` → `Record` → `Aggregate`.
- Реализовать метод `IsAssignableFrom()` для проверки совместимости типов через иерархию наследования: переданный тип совместим с текущим, если он либо идентичен ему, либо находится ниже в цепи наследования (т.е. является более специализированным).
- Разрешить создание **произвольных типов** с указанием базового типа через конструктор для расширяемости.

## Аргументы (причины выбора)

### 1. Type Safety в runtime
- Предотвращает логические ошибки при соединении несовместимых портов.
- Валидация типов происходит до создания соединения.

### 2. Ковариантность (Liskov Substitution Principle)
- `Aggregate` может быть использован везде, где требуется `Record` или `RawRecord`.
- Снижает связанность: узлы работают с базовыми типами, но получают специализованные.

### 3. Расширяемость
```
public static readonly DataType TimeSeries = new("TimeSeries", Aggregate);
public static readonly DataType Matrix = new("Matrix", Aggregate);
```

Новые типы легко добавляются без изменения ядра системы.

### 4. Сериализация и метаданные
- Тип хранит свое имя, что позволяет сохранять конвейеры в JSON/YAML с сохранением информации.
- Отладка и логирование: видно, какой тип был использован.

### 5. Предметная область (Domain-Driven Design)
- `DataType` — явное **value object**, выражающее понятие типа данных в бизнес-логике.
- Имеет четкую семантику: имя + иерархия.

## Альтернативы (и причины отказа)

### 1. Использовать обычные строки (enum или string)
```enum PortType { RawRecord, Record, Aggregate }```

- **Недостаток**: нет расширяемости без изменения enum; нет иерархии.
- **Недостаток**: сложнее добавить метаинформацию (описание, constraints).

### 2. Использовать System.Type (C# reflection)
```var portType = typeof(MyRecord);```

- **Недостаток**: требует реальных C# классов для каждого типа; излишняя сложность.
- **Недостаток**: сложнее сериализовать и совместимо с .NET only.

### 3. Отсутствие системы типов (портятся напрямую)
- **Недостаток**: ошибки типов выявляются только во время выполнения конвейера.
- **Недостаток**: плохая масштабируемость и debugging.

### 4. Использовать class вместо record
```public class DataType { }```

- **Недостаток**: ненужная сложность для простого value object.
- **Недостаток**: больше аллокаций, сложнее тестировать.

## Недостатки и компромиссы

- **Циклические зависимости типов**: если создать цикл (A → B → A), `IsAssignableFrom` может зациклиться. 
  - валидировать иерархию при создании в конструкторе (опционально).
  
- **Жесткая иерархия**: система не поддерживает множественное наследование.
  - достаточно для большинства use-case; если нужно, переходить на interface-based.

- **Глубокие иерархии могут снижать производительность** при частых проверках `IsAssignableFrom()`.
  - незначительно для типичных конвейеров; можно оптимизировать кэшированием результатов.

## План внедрения

1. Сохранить текущую реализацию `DataType` в `src/ReactivePipelineEditor.Domain/Ports/DataType.cs`.
2. Использовать `DataType` в определении портов:
```public record Port(PortName Name, DataType Type);```
3. Добавить валидацию при соединении портов:
```if (!targetPort.Type.IsAssignableFrom(sourcePort.Type)) throw new InvalidOperationException("Type mismatch");```

4. Покрыть полным набором юнит-тестов (см. `DataTypeTests.cs`).
5. Документировать расширение типов в README.

## Примеры использования

### Определение пользовательского типа
```var customType = new DataType("CustomData", DataType.Aggregate);```

### Проверка совместимости
```
var sourceType = DataType.Aggregate;
var targetType = DataType.Record;
if (targetType.IsAssignableFrom(sourceType))
	Console.WriteLine("Compatible!");  // Выведет, т.к. Aggregate наследует Record
```

### Сохранение в конфиге
```{ "port": { "name": "output", "type": "Aggregate" } }```

## Вывод

Система типов `DataType` обеспечивает баланс между **типобезопасностью**, **расширяемостью** и **простотой реализации**. 
Она явно выражает доменную модель (типы данных в конвейере) и позволяет валидировать соединения на этапе структурирования конвейера, 
а не в runtime обработки. Рекомендуется принять и использовать как основу для типизации портов.
